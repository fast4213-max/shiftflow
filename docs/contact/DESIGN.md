## 1. 画面

```
index.html     [利用者]タブ: お知らせ(最大3件)→ 社員番号・PIN → ログイン
               「はじめての方は 新規登録・使い方」/「ログインできないときは お問い合わせ」
contact.html   ログイン前: 入力 → 送信 → 受付番号(+確認コード)/「返事を見る」
               ログイン後: 自動の欄 + 入力 → 送信 / これまでのお問い合わせと返事
notices.html   ログイン後: 表示中のお知らせ全部
admin.html     タブを追加: 「お問い合わせ」(未対応の数)・「お知らせ」
```

管理の「お問い合わせ」タブ: 左に一覧(要対応・返信済み・すべて・受信メール)、右にやり取り(画面/メール送信/メール受信の札)と返事の欄。
返事は「メール(同じスレッドに返信)」か「画面だけ」。「対応済みにする」「Gmailで開く」。送れたかどうかを残す。

## 2. しくみ

```
送る:  管理画面 → Edge Function admin-contact → GAS(doPost・合言葉)→ Gmail で送信(スレッドIDを返す)
受ける: GAS の5分ごとのトリガー → 未取り込みのメールを Edge Function mail-inbound へ(合言葉)
        → inquiry_messages に追加 → Discord「📨 メールで返信が来ました #0012」
```

どの問い合わせへの返信かは、(1) 送ったスレッドID → (2) 件名の `#0012` → (3) どれでもなければ「受信メール」。

| 種類 | 内容 |
|---|---|
| 画像 | 画面で縮小(長い辺1600px・JPEG)して位置情報などを消す → `contact` → GAS → 専用 Gmail 自身に「【shiftflow 受付】#0012 …(画像2枚)」を添付つきで送る(ラベル `shiftflow/受付`)。Discord の通知にも画像を添付(1通に Embed +画像)。管理画面には「画像2枚(Discord・Gmailで見る)」だけ |
| 消す作業 | GAS の1日1回のトリガー: Gmail の90日より古い `shiftflow` ラベルのメールをゴミ箱へ → Edge Function `maintenance`(合言葉)を呼び、DB の古い問い合わせを消し、記録してある Discord のメッセージIDの通知を Webhook で削除 |
| テーブル `notices` | id, title, body, level(info/important), starts_on, ends_on, created_at, updated_at |
| テーブル `inquiries` | id(受付番号), user_id(null可・on delete set null), logged_in, employee_no, name, office_name, kind, reply_via(screen/mail), email, code_hash, status(open/replied/done), last_activity_at, created_at |
| テーブル `inquiry_messages` | id, inquiry_id(null可=受信メール), sender(user/admin/mail), channel(web/mail), body, from_email, gmail_message_id(一意), gmail_thread_id, mail_status(sending/sent/failed/unknown), created_at |
| 未ログインで読む関数 | お知らせ(表示中)と区所の名前だけを返す(`keepalive` と同じく anon に実行権限) |
| Edge Functions | `contact`(送信・返事を見る)、`admin-contact`(返事・状態)、`mail-inbound`(GAS から) |
| GAS | doPost(送信)と、5分ごとの受信の取り込み。メールの取り込み状態はラベルで管理 |
| シークレット | `DISCORD_WEBHOOK_URL` / `MAIL_RELAY_URL` / `MAIL_RELAY_SECRET` |
| いたずら対策 | 送信は回数制限(接続元・社員番号・ログイン後は利用者ごと)。内容1000文字、取り込むメール5000文字 |

## 3. 本人がやること(実装後に手順書)

1. 専用 Gmail を作る(2段階認証オン、ほかに使わない)
2. Discord のチャンネルと Webhook の URL
3. その Gmail で GAS にコードを貼る → ウェブアプリとして公開(全員)→ 5分ごとのトリガー
4. Supabase の Secrets に3つを入れる

## 5. デバッグのときの確かめ方(案)

- Deno のテスト: Embed の組み立て(長さ・空の欄・メンションの無効化)、メールアドレスの正規化、確認コードの比べ方、引用の取り除き、回数制限のキー
- 本物の PostgreSQL に migration を当てて: 未ログイン・利用者・管理者・サーバー専用それぞれで、3つのテーブルが設計どおりにしか読み書きできないこと(X1・X2)、利用者の削除(X7)、自動削除(X8)
- Chromium で: ログイン画面のお知らせ(0件・3件・読み込み失敗・遅い)、問い合わせ(ログイン前・後、メールと画面の切り替え、二度押し、幅320)、管理画面のやり取り
- 画像: iPhone(HEIC・縦向き)・Android・PC から1〜3枚、5MB の写真、画像でないファイル、画像の転送の失敗
- GAS: 自分宛て・Gmail・携帯会社のアドレスへの送受信、二度押し、引用つきの返信、不達、トリガーの重なり

## 6. 実装で決めたこと(設計からの具体化・2026-10-06)

- 問い合わせの3つの表(`inquiries`・`inquiry_messages` など)は、画面から直接は読めない(anon / authenticated に権限なし)。すべて Edge Function(service_role)経由。お知らせだけ、管理者が画面から直接書く(RLS)
- 未ログインで呼べる DB の関数は `current_notices()`(お知らせ)と `contact_offices()`(区所の名前だけ)を足した
- 確認コードは画面が作る(8文字・紛らわしい文字なし)。送り直しても同じコードになり、DB にはハッシュだけ保存
- ログイン後の送信は `mode: "member"` を付けて送る。ログインが切れていたらログイン前として送らずにエラーにする(C3)
- 回数制限は `rate_limit_hit()`(1回の文で数える)。接続元20件/時、社員番号・利用者ごと5件/時、返事を見るのは接続元30回/時・受付番号ごと10回/時
- 画像は送信を待つ(届いたかを画面で知らせるため)。画像がないときは Discord の通知を待たずに返す
- GAS の送信は、key(返事ごとの request_key)で二重送信を防ぐ(GAS のスクリプト プロパティに30日覚える)。相手のメールがあればそのメールに返信(`createDraftReply`)、無ければ shiftflow の件名でだけ新しく送る
- 受信メールは、GAS が14日分の受信トレイを5分ごとに見て、まだ渡していないもの(6時間覚える)を送る。DB が Gmail のメッセージIDで二重を防ぐ。自分のメール・Google からのお知らせは送らない
- 古いものの削除は、DB の pg_cron(毎日 3:20)と、GAS の毎日4時の処理(Gmail・Discord・DB)の両方
