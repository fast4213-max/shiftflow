# お問い合わせ・お知らせ のセットアップ手順

お問い合わせ・お知らせを使えるようにする手順です。ブラウザだけでできます(全部で20〜30分)。
設計は [`DESIGN.md`](DESIGN.md)。

| 使うもの | 状態 |
|---|---|
| 専用 Gmail `shiftflow.kinmu@gmail.com` | 作成済み(2026-10-06) |
| Discord のチャンネル `#勤務登録-お問合せ` と Webhook「shiftflow」 | 作成済み(2026-10-06) |

**お知らせ**は、main に反映すればすぐ使えます(管理画面の「お知らせ」タブ)。下の手順は、**お問い合わせ**の通知とメールのためのものです。
手順の途中でも、お問い合わせの受付自体はできます(通知やメールが届かないだけで、管理画面の「お問い合わせ」タブで見られます)。

---

## 1. Discord の Webhook の URL を Supabase に入れる

1. Discord の `#勤務登録-お問合せ` の「チャンネルの編集」→「連携サービス」→「ウェブフック」→「shiftflow」→「**ウェブフックURLをコピー**」
2. Supabase のダッシュボード →「Edge Functions」→「Secrets」→「Add new secret」
   - Name: `DISCORD_WEBHOOK_URL`
   - Value: コピーした URL(`https://discord.com/api/webhooks/...`)

> URL は秘密です。チャット・GitHub・スクリーンショットに出さないでください。漏れたら Discord で「ウェブフックを削除」して作り直し、ここを入れ替えます。

## 2. GAS(メールの中継)を作る

**必ず `shiftflow.kinmu@gmail.com` でログインした状態で**行います(ほかのアカウントで作ると、そのアカウントからメールが送られます)。
ブラウザで複数の Google アカウントにログインしているときは、右上のアイコンで `shiftflow.kinmu@gmail.com` に切り替えてから開いてください。

1. <https://script.google.com/> →「新しいプロジェクト」。名前を「shiftflow お問い合わせ」にする
2. 左の「コード.gs」の中身を全部消して、[`gas/Code.gs`](gas/Code.gs) の中身を全部貼り付けて保存(💾)
3. 左の歯車「プロジェクトの設定」
   - 「タイムゾーン」を「(GMT+09:00) 日本標準時」にする
   - いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
     - プロパティ `HOOK_URL` / 値 `https://owotkyocoslifbgwwafm.supabase.co/functions/v1/mail-inbound`
4. エディタに戻り、上の関数の選び方で `makeSecret` を選んで「実行」
   - 初めてのときは「承認が必要です」→ アカウントを選ぶ →「詳細」→「(安全ではないページ)に移動」→「許可」
     (自分で作ったスクリプトなので、この表示が出ます)
   - 下の「実行ログ」に出た64文字の合言葉をコピーする
5. Supabase の「Edge Functions」→「Secrets」に追加
   - Name: `MAIL_RELAY_SECRET` / Value: コピーした合言葉
6. GAS の右上「デプロイ」→「新しいデプロイ」→ 歯車 →「ウェブアプリ」
   - 説明: shiftflow
   - 次のユーザーとして実行: **自分(shiftflow.kinmu@gmail.com)**
   - アクセスできるユーザー: **全員**
   - 「デプロイ」→ 表示された「ウェブアプリの URL」(`https://script.google.com/macros/s/.../exec`)をコピー
7. Supabase の「Edge Functions」→「Secrets」に追加
   - Name: `MAIL_RELAY_URL` / Value: コピーした URL(最後が `/exec`)
8. GAS のエディタで `setup` を選んで「実行」
   - 実行ログに「Supabase とつながりました」と出れば完了(ラベルと、5分ごと・毎日4時のトリガーができます)
   - 「HOOK_URL」や「Supabase 401/404」のエラーが出たら、3・5 の値と、main への反映(手順3)が済んでいるかを確かめる

> **GAS のコードを直したとき**: 保存したあと「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新しいバージョン」→「デプロイ」。
> 「新しいデプロイ」にすると URL が変わってしまいます(そのときは Supabase の `MAIL_RELAY_URL` も入れ替える)。

## 3. 反映と確認

1. main に反映されると、GitHub Actions で DB・Edge Functions・画面が自動で更新されます
2. 管理画面 →「お問い合わせ」タブの上に、次のように出れば準備完了
   - 「メールの取り込み(GAS): 最後に確認 ○分前 ・ 今日送れる残り 100通」(緑)
   - 「Discord の Webhook が未設定」「メールの中継(GAS)が未設定」が**出ていない**
3. 試しに、ログアウトした状態で「お問い合わせ」から、自分のメールアドレス・画像1枚を付けて送る
   - Discord に通知(画像つき)が来る / Gmail に「【shiftflow 受付】」のメールが来る
   - 管理画面の「お問い合わせ」タブで、メールで返事を送る → 自分のアドレスに届く(迷惑メールフォルダも見る)
   - そのメールに返信する → 5分ほどで管理画面に「新着メール」として出て、Discord にも通知が来る

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| Discord に通知が来ない | `DISCORD_WEBHOOK_URL` の値(`https://discord.com/api/webhooks/数字/文字` の形か)。Webhook を削除・作り直していないか |
| メールで返事を送ると「GAS の応答を読めません」 | ウェブアプリの「アクセスできるユーザー」が「全員」か。`MAIL_RELAY_URL` の最後が `/exec` か |
| 「合言葉が違います」 | GAS の `SECRET` と Supabase の `MAIL_RELAY_SECRET` が同じか(前後の空白に注意) |
| 「最後に確認 ○分前」が30分以上 | GAS の左の時計「トリガー」に `pollInbox` があるか。「実行数」にエラーが無いか。Google から「承認が必要」のメールが来ていないか(来ていたら `setup` をもう一度実行) |
| 返信したメールが管理画面に出ない | 迷惑メールフォルダに入っていないか(迷惑メールは取り込みません)。14日より古いメールは取り込みません |
| 「今日送れるメールの数の上限です」 | 無料の Gmail は1日100通まで。翌日に「もう一度送る」 |

## 消えるもの(3か月)

- 問い合わせ・やり取り: 最後のやり取りから90日で DB から消える(毎日 日本時間 3:20、`purge_old_contact()`。GAS の毎日4時の処理からも呼ぶ)
- メールアドレス: 対応済みにして30日、やり取りが無ければ先に消える
- Gmail: ラベル `shiftflow` のスレッドで、最後のメールから90日たったものをゴミ箱へ(30日は戻せる)
- Discord: 通知から90日で消える(GAS の毎日4時の処理)
