# 非番を2件で登録する・非番用カレンダー(設計)

状態: **実装済み(2026-10-08)**。6章の4つは本人が決めた(2026-10-08)。migration は `20261008000000_offduty_events.sql`

公開リポジトリなので、カレンダーID・個人情報・マスタの実データは書かない。

## 1. やりたいこと

- 「出勤を2件で登録」と同じように、**非番も2件**(終日の「〜」+ 退勤時間の時間つきの予定)にしたい人が出てきた
- 非番の時間の予定の色を変えたい人のために、**3つ目のカレンダーID(非番用)** を登録できるようにする(Googleカレンダーの色はカレンダーごとなので、色を変えるにはカレンダーを分ける)
- 非番用カレンダーに入るのは**時間の予定(2件目)だけ**。終日の「〜」は今までどおり勤務用
- 色が勤務と同じでよい人は、今までどおり**勤務用のカレンダーIDだけ**で使える(非番用は空のままでよい)

## 2. 設定(利用者が選ぶもの)

設定画面の「3. カレンダーIDを入力して接続テスト」に2つ足す。

| 項目 | 列(user_settings) | 空・オフのとき |
|---|---|---|
| 非番を2件で登録する | `split_offduty_events boolean not null default false` | 非番は1件(今までどおり) |
| 非番の時間用カレンダーID(なくてもよい) | `offduty_calendar_id text not null default ''` | 非番の時間の予定は**勤務用**に入る。休日用の「空なら登録しない」とは違う |

- 「出勤を2件で登録する」(`split_day_events`)とは**別のチェック**にする(Q4)。今「出勤を2件」にしている人の非番が、何もしないのに勝手に2件にならないように
- 非番用カレンダーは「非番を2件」の時間の予定にしか使わない。チェックが無いときは、IDを入れても何も入らない(画面で「非番を2件で登録する」にチェックを入れた人だけ使う、と書く。IDの欄はチェックが無いときも入力できる・接続テストもする)
- 非番用に勤務用と同じIDを入れても、空と同じ動き(勤務用に入る)
- 非番用に休日用と同じIDを入れてもよい(非番の時間と休みを同じ色にしたい人)

組み合わせ

| 非番を2件 | 非番用ID | 非番の予定 |
|---|---|---|
| オフ | (どちらでも) | 勤務用に「〜」1件(今と同じ) |
| オン | 空 | 勤務用に「〜」+ 時間の予定の2件(勤務と同じ色) |
| オン | あり | 勤務用に「〜」、非番用に時間の予定(時間の予定だけ非番の色) |

## 3. 非番の2件目(時間の予定)

- 1件目: 今と同じ終日の「〜」(勤務用。メモ=退勤時間)
- 2件目: メモの1行目の**退勤時間**から始まる、時間つき1時間の予定(日本時間)。**タイトルは時間だけ**(例「9:02」。Q2)。メモなし
- 時間の読み方: 今の `parseTimeRange` と同じく全角・「～」なども読む。加えて非番用に
  - 先頭の「〜」を許す(「〜9:02」と手で書いた人)
  - 「8:30〜9:02」のように2つあれば、**後ろ**を退勤とみなす
  - タイトルは読んだ退勤時間を「H:MM」に直したもの(「〜９：０２」と書いても「9:02」)
  - 24時以降・時間でないメモ(手で「休み」などに書き換えた)は、1件のまま
- 対象(Q3)
  - 自動の非番(泊の翌日。kind=`offduty`)
  - **手入力の非番**: マスタにない番号で、「〜」「-」「→」など記号だけのもの・「非」「明」だけのもの・「非番」「明け」「明番」を含むもの(今の `isOffTitle` のうち「休」の判定を除いた部分。関数を分ける)。手入力の非番は、メモに退勤時間を書いたときだけ2件になる
  - 「公休」「年休」など「休」を含む手入力は休みなので、今までどおり1件
- 2件目の印(`extendedProperties.private.shiftflow`)は1件目と同じ(自動の非番は `offduty`、手入力の非番は `day`)。削除・翌月1日・2日の扱いは今の「印で探す」がそのまま効く(時間つきの予定は日本時間の日付で拾っている)
- 月末が今回はじめて泊になり、翌月1日が新しく非番になるとき(W6)、翌月1日の番号の無いメモ(別の用事のメモ)は非番のメモに使わず、そのメモだけの記録を消す(月の中で新しく非番になった日のメモを画面が消すのと同じ)。前から泊だった(本人が非番のメモを手で書いた)ときは、今までどおりそのメモを使う。判断は `register-month` の `nextFirstNewlyOffduty`
- 「出勤を2件」がオンで「非番を2件」がオフのとき、手入力の非番は今までどおり1件

## 5. 気をつけること

- **非番用のIDをあとから足した・変えたとき**: 前のカレンダー(勤務用など)にある登録済みの時間の予定は、その月を登録し直しても消えない(今の「カレンダーIDを変えたとき」と同じ。U1 で使い方に書いた手順: 変える前にリセットするか、前のカレンダーの予定を手で消す)。使い方の「カレンダーを変えたい」にも非番用のことを一言足す
- 接続テストは、IDを入れた全部のカレンダーに書けたときだけ通る(1つでも書けなければ登録できない)
- Google への書き込みが非番の日の分だけ増える(1か月で10件前後)。今の120秒の時間内に収まる見込み
- GAS(お問い合わせ)は関係なし。貼り直し不要
