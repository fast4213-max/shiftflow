# 非番を2件で登録する・非番用カレンダー(設計)

状態: **設計のみ(未実装)**。下の「決めてほしいこと」が決まったら実装する。

公開リポジトリなので、カレンダーID・個人情報・マスタの実データは書かない。

## 1. やりたいこと

- 「出勤を2件で登録」と同じように、**非番も2件**(終日の「〜」+ 退勤時間の時間つきの予定)にしたい人が出てきた
- 非番の色を変えたい人のために、**3つ目のカレンダーID(非番用)** を登録できるようにする(Googleカレンダーの色はカレンダーごとなので、色を変えるにはカレンダーを分ける)
- 色が勤務と同じでよい人は、今までどおり**勤務用のカレンダーIDだけ**で使える(非番用は空のままでよい)

## 2. 設定(利用者が選ぶもの)

設定画面の「3. カレンダーIDを入力して接続テスト」に2つ足す。2つは別々に選べる。

| 項目 | 列(user_settings) | 空・オフのとき |
|---|---|---|
| 非番用カレンダーID(なくてもよい) | `offduty_calendar_id text not null default ''` | 非番は**勤務用**に入る(今までどおり)。休日用の「空なら登録しない」とは違う |
| 非番を2件で登録する | `split_offduty_events boolean not null default false` | 非番は1件(今までどおり) |

- 「出勤を2件で登録する」(`split_day_events`)とは**別のチェック**にする。今「出勤を2件」にしている人の非番が、何もしないのに勝手に2件にならないように
- 非番用に勤務用と同じIDを入れても、空と同じ動き(勤務用に入る)
- 非番用に休日用と同じIDを入れてもよい(非番と休みを同じ色にしたい人)

組み合わせ

| 非番用ID | 非番を2件 | 非番の予定 |
|---|---|---|
| 空 | オフ | 勤務用に「〜」1件(今と同じ) |
| 空 | オン | 勤務用に「〜」+ 時間の予定の2件(勤務と同じ色) |
| あり | オフ | 非番用に「〜」1件(色だけ変わる) |
| あり | オン | 非番用に「〜」+ 時間の予定の2件(2件とも非番の色) |

## 3. 非番の2件目(時間の予定)

- 1件目: 今と同じ終日の「〜」(メモ=退勤時間)
- 2件目: メモの1行目の**退勤時間**から始まる、時間つき1時間の予定(日本時間)。タイトルは「〜9:02」のように「〜」+退勤時間(案。決めてほしいこと Q2)
- 時間の読み方: 今の `parseTimeRange` と同じく全角・「～」なども読む。加えて非番用に
  - 先頭の「〜」を許す(「〜9:02」と手で書いた人)
  - 「8:30〜9:02」のように2つあれば、**後ろ**を退勤とみなす
  - 24時以降・時間でないメモ(手で「休み」などに書き換えた)は、1件のまま
- 2件目の印(`extendedProperties.private.shiftflow`)は1件目と同じ `offduty`。削除・翌月1日・2日の扱いは今の「印で探す」がそのまま効く(時間つきの予定は日本時間の日付で拾っている)
- 対象は**自動の非番(泊の翌日。kind=offduty)だけ**。手入力で「〜」「非番」と入れた日は、今までどおり勤務用に1件(Q3)

## 5. 気をつけること

- **非番用のIDをあとから足した・変えたとき**: 前のカレンダー(勤務用など)にある登録済みの非番は、その月を登録し直しても消えない(今の「カレンダーIDを変えたとき」と同じ。U1 で使い方に書いた手順: 変える前にリセットするか、前のカレンダーの予定を手で消す)。使い方の「カレンダーを変えたい」にも非番用のことを一言足す
- 接続テストは、IDを入れた全部のカレンダーに書けたときだけ通る(1つでも書けなければ登録できない)
- Google への書き込みが非番の日の分だけ増える(1か月で10件前後)。今の120秒の時間内に収まる見込み
- GAS(お問い合わせ)は関係なし。貼り直し不要
