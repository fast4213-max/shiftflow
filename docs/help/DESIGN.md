# 使い方ページの組み替え(設計案)

2026-11-03 本人の依頼。対象は `web/help.html`・`web/js/help.js`・`web/css/help.css`。**実装済み(2026-11-03。「7. 決めてほしいこと」の4つは、案のとおりに決まった)。**

実装メモ: 節は `<details class="fold">`(小さい節は `fold sub`)。昔のリンク(`#intro`・`#signup`・`#settings`・`#prepare`・`#share`・`#id`・`#test`)は、`help.js` の ALIAS で新しい節に飛ぶ(`#share`・`#test` は見出しの id がそのまま残っている)。印刷のときは beforeprint で全部開く。設定画面の名前に合わせて、「出勤を2件で登録する」を「出勤を2段で出す」、「非番を2件で登録する」を「非番を2段で出す」に言い換えた(Google に登録する人向けの説明の中の「2件」はそのまま)。

## 1. 何を変えたいか(依頼の整理)

1. 「はじめに: 全体の流れ」と「新規登録とログイン」は要らない(画面を見れば分かる)
2. Google カレンダー連携の**前**に、「アプリのカレンダーを使う人の設定」を置く(区所を選ぶ → カレンダーの表記を選ぶ → 保存)。画面のとおりに分かる書き方で、折りたためる
3. Google カレンダー連携は、**スマホで設定する**と**パソコンで設定する**の2つに分ける。どちらも折りたためる

背景: 新しい人は、Google 連携なし(保存だけ)で始まる(2026-11-03 変更)。今の使い方は、Google 連携を前提に書かれていて、最初に読む人が迷う。

## 4. 折りたたみのしかた

- `<details class="more"><summary>…</summary>…</details>` を、節の見出しごとに使う(設定ページの「詳しい説明」と同じ作り。`details.more` の見た目は `web/css/app.css` にある)
- 目次(上のリンク)を押したら、その節が自動で開く(`help.js` に数行。`#share`・`#test` など、ほかのページからのリンク[`settings.html`]も同じ)
- 「全部開く / 全部閉じる」のボタンを、目次の横に1つ(印刷・検索のため)
- 印刷のときは、全部開く(CSS の `@media print`)

## 5. 画像(スクリーンショット)

- 今の画像(`web/img/manual/`)は全部スマホの画面。5-A(スマホ)と、1(設定)で使い続ける
- 5-B(パソコン)は、**画像なし**の文章だけで書く(Google カレンダーの画面は変わりやすいため)。画像が欲しければ、パソコンの画面を撮ってもらう
- 使わなくなる画像(`login.png`・`register.png`)は、残すか消すか決める(容量は小さい。残しても害はない)

## 6. 作業と確認

- 変えるのは `web/help.html`・`web/js/help.js`・`web/css/app.css`(必要なら)・`web/settings.html` のリンク。DB・関数は変えない。反映は GitHub Pages だけ
- 画面テストに足す: 目次を押すと節が開く / 最初は 1 だけ開いている / 「全部開く」で全部開く / 古いリンク(`#share`・`#test`)で正しい節が開く / `#signup` などの消した節のリンクで、エラーにならない
- 使い方ページの説明が、設定ページ・勤務入力の画面の文言(「保存」「リセット」「登録」)と食い違わないか読み合わせる

## 7. 決めてほしいこと

1. 「登録される予定」の表は、5-D に**移して残す**でよいか(案)、それとも消すか
