# カレンダーの共有(仲間・夫婦)の設計(2026-11-11 決定)

TimeTree のような「カレンダーを人と共有する」機能。相談で決めた内容と、作り方をまとめる。

## 目的と、TimeTree との違い
| | TimeTree | shiftflow |
|---|---|---|
| 形 | 共有カレンダーを1つ作り、全員で使う | **仲間**: 自分のカレンダーに、相手の勤務を重ねて出す。**夫婦**: 招待した側のカレンダーを2人で一緒に使う |
| 招待 | URL・QRコード | 相手の社員番号を入れて送る → 相手の「お知らせ」に届く → 「共有する」 |
| 見える範囲 | 全部 | 仲間は勤務だけ / 勤務と休日。夫婦はカレンダーまるごと |
| 編集 | 全員 | 仲間は見るだけ。夫婦は2人とも |

## 1. 共有の種類
| | 仲間 | 夫婦 |
|---|---|---|
| 人数 | 共有中+自分が送った返事待ちで **5人まで**(夫婦の相手も1人と数える) | 1人だけ(1組まで) |
| できること | 相手の勤務(と休日)を見る | 招待した側のカレンダーを2人で使う+相手の勤務(と休日)も出る |
| 編集 | 見るだけ | 2人とも |
| 勤務を見せる範囲 | 勤務だけ / 勤務と休日 / 見せない(見るだけ)。それぞれが自分の範囲を決める(一方通行もできる) | 同じ |

- 「勤務」には、非番(「〜」とその時間)も入る。
- 仲間に予定まで見せる「全部」は作らない(予定まで見せたいときは夫婦)。

## 2. ラベル
### 仲間
- 相手ごとに **名前のラベル** を作る。見せる範囲が「勤務だけ」なら1つ(`田中`)、「勤務と休日」なら2つ(`田中`・`田中・休`)。見せないなら作らない。
- 名前の初期値は、仲間は相手の苗字(夫婦のラベルは下の名前)。名前と色は **見る人がそれぞれ決める**(相手には関係しない)。自分のラベルの上限(10個)には数えない。
- 相手が範囲を変えたら、ラベルの数も変わる。色は覚えておくので、戻したら前の色に戻る。
- 上のラベルのボタンに並ぶ(押すと隠せる。自分の画面だけ)。

### 夫婦
**夫婦のカレンダーのラベルは、名前も色も2人で同じ。片方が変えたら相手も変わる。ただし「自分だけ」のラベルは、作った人にしか見えない。**

例: 太郎(招待した側)と花子(招待された側)が、2人とも「勤務と休日」を見せている。2人の画面に同じラベルが出る。
```
[太郎] [太郎・休] [花子] [花子・休] [通院] [旅行] ...
```
| ラベル | どちらに出る | 色・名前を変えたら |
|---|---|---|
| 勤務・休日(・非番)の名前のラベル | 2人とも | 相手も変わる |
| 自分で作ったラベル | 2人とも(片方が作れば相手にも出る) | 相手も変わる |
| 自分で作ったラベル(「自分だけ」にチェック) | 作った人だけ。そのラベルの予定も相手に出ない | 自分だけ |
| 仲間の名前のラベル(例: 花子の仲間の `田中`) | その仲間と共有している人だけ | 自分だけ |

- 一緒に使うあいだは、自分の勤務も「勤務」ではなく自分の名前のラベルになる(2人が同じラベルを見るので)。始めたときの色は、それぞれ今の勤務・休日の色を引き継ぐ。
- 「勤務だけ」の人は休日のラベルを作らない。`花子・非` のラベルも作るが、相手の勤務は1段で出す(非番の帯が分かれない)ので、ボタンは出さない。
- 1人ずつのもの: ラベルのボタンで隠すこと・このカレンダーに出すもの・アイコン・色合い。
- やめたとき: 招待した側はラベルの名前が「勤務」「休日」「非番」に戻る(色はそのまま)。招待された側は、一緒に使う前の自分のラベルに戻る。

## 3. マスの中の表記
- **見る人のいつもの設定どおり**(名前に時間・時間つき・泊など)。ただし **出勤・非番を2件にする設定(2段)は相手の勤務には使わず、いつも1段**で出す。誰の勤務かはラベルの色で見分ける。
- 時間・泊地は **相手の区所のマスタ** から出す(区所が違っても正しい時間)。
- 並び: 自分の勤務 → 自分の予定 → 名前のラベル(並び順どおり)。入りきらなければ「+N」。日の詳細では誰の勤務かを出す。
- 「画像にする」は、画面と同じ(ボタンで隠した人は入らない)。

## 4. 招待と返事
### 場所
カレンダーの右下「設定」→ **アイコンの設定のすぐ上** に「👥 カレンダーの共有」。
```
👥 カレンダーの共有                     3/5人
 共有している人
   花子 (夫婦)  見せる範囲[勤務と休日▼]  相手から: 勤務と休日   [やめる]
   田中 (仲間)  見せる範囲[勤務だけ▼]    相手から: 勤務と休日
               ラベル [田中■] [田中・休■]                     [やめる]
 返事待ち
   1234567 さんへ(仲間・11/25まで)                            [取り消す]
 届いているお誘い(お知らせと同じもの)
 新しく共有する
   相手の社員番号[_______]  種類(●仲間 ○夫婦)
   見せる範囲(●勤務だけ ○勤務と休日 ○見せない)   [送る]
```
### 送る
- 相手がいてもいなくても「送りました(相手が使っていれば届きます)」と同じ文(登録しているか探れないように)。いない番号あてのお誘いも、期限まで「返事待ち」に出る。
- 1日10回まで。期限は14日。自分あては送れない。すでに共有している人には送れない(番号は分かっているので、探れることにはならない)。
- 送る側には、相手が「共有する」を押すまで名前を出さない(入れた番号だけ)。
### 受け取る
- `notices.html` のいちばん上に「あなたへのお知らせ」。返事をするまで赤い点(カレンダーの「設定」、設定の中の「📢 お知らせ」)。
- [共有する] [断る]。自分の見せる範囲はここで選ぶ。
- 夫婦のお誘いでは、今の自分の予定・TODOなどを **取り込む / 取り込まない** を選ぶ。取り込まなくても元のデータは消えない(一緒に使うあいだは隠れる)。
- 自分か相手がすでに5人のとき・夫婦がすでにいるときは「共有する」で理由を出す。
### 断られたとき・期限切れ
送った側には「共有されませんでした」とだけ出す(どちらかは区別しない)。✕で消せる。30日たつと自動で消える。
### やめる・範囲を変える
どちらからでも、いつでも。相手には通知しない(相手が次に読み込んだときに消える・変わる)。

## 5. 夫婦: 一緒に使う
| 2人で同じ | 1人ずつ |
|---|---|
| 予定・自分で作ったラベル(名前・色)・名前のラベル(名前・色)・TODO・重要メモ・スタンプ・画像の置き場(**20枚**)・予定の写真・テンプレート・アナウンス | 「自分だけ」のラベルとその予定・仲間の名前のラベル・ラベルのボタンでの表示・このカレンダーに出すもの・アイコン・色合い・勤務入力 |

- 予定の詳細に「花子が追加」と出す。
- 予定を同時に直したときは「相手か別の端末で変更されたか、消されています」(今の version の仕組み)。TODO・重要メモは、あとから保存したほうが残る。
- 相手の変更は、開いたとき・画面に戻ったとき・月を移ったとき(1分に1回まで。開いている画面があるときは読み直さない)に読み直して出る。
- 予定などの上限(予定5,000件・ラベル10個など)は、カレンダー1つ分を2人で使う。画像の置き場だけ20枚。
### 取り込む(招待された側が選んだとき)
- 招待された側の予定・TODO・重要メモ・テンプレート・画像・スタンプを、招待した側のカレンダーへ **移す**(コピーではない。やめるときに持って帰るので、二重にならない)。
- ラベルは、同じ名前があればそれにまとめる。無ければラベルも移す。10個を超える分は「取り込み」ラベルにまとめる。
### やめるとき(どちらからでも・退会も同じ)
- 招待した側のカレンダーはそのまま残る。招待された側は自分のカレンダーに戻る。
- **招待された側が作った(取り込んだものを含む)予定・TODO・重要メモ・テンプレート・画像・写真・スタンプの種類は、招待された側のカレンダーへ移す**。招待した側の手元には残らない。スタンプは種類についていく(相手の作った種類で押したスタンプは、相手に残る)。
- 予定のラベルは、戻った先で同じ名前のラベルにつけ直す。無ければ作る(10個を超えるときは「その他」)。
- 確認画面で「花子さんが作った予定 12件・写真 3枚は、花子さんのカレンダーに移ります」と出す。

## 6. データ
### 新しい表
| 表 | 中身 |
|---|---|
| `cal_share_invites` | お誘い。from_id・to_id(いない番号なら null)・to_employee_no・kind(mate/couple)・from_scope・status(pending/accepted/declined)・expires_at |
| `cal_share_links` | 共有している2人(1組1行)。user_a・user_b・kind・inviter_id・scope_a(a が b に見せる範囲)・scope_b。scope は none/duty/duty_off |
| `cal_share_views` | 仲間の名前のラベル(見る人ごと)。viewer_id・owner_id・name・color・off_name・off_color・sort |
| `cal_share_sends` | 送った記録(1日10回の数え上げ用) |

- 読み書きはすべて SQL 関数(security definer)で行う。お誘いの表(invites)は直接読めない(送った人が to_id・status を見て、相手が登録しているかを探れないように。AR1)。links・views は本人に関係する行を読むだけ(views は名前・色・並びだけ直せる)。
- 共有する・やめる・範囲の変更・取り込み・持って帰るは、1つの関数の中で済ませる(半分だけ、を防ぐ)。人数の上限は、2人分を順番にロックしてから数える(同時に押しても超えない)。
- 社員番号から人を探すのは関数の中だけ(`profiles` は今までどおり本人しか読めない)。

### 夫婦のための変更(第2段階)
- 関数 `cal_owner()`: 夫婦なら招待した側、それ以外なら自分。
- 予定などの表(cal_labels・cal_events・cal_photos・cal_stamp_defs・cal_stamps・cal_todos・cal_importants・cal_gallery・cal_templates)の RLS を `user_id = auth.uid()` から `user_id = cal_owner()` に。`created_by`(作った人)の列を足す。user_id の初期値も `cal_owner()`。
- `cal_labels` に `member_id`(誰の勤務の名前のラベルか)と `private_to`(自分だけ)。自分だけのラベルとその予定・テンプレートは、RLS で作った人にしか見えない。 「自分だけ」にできるのは、相手が作った予定・テンプレートが入っていないラベルだけ(トリガー `cal_labels_private_check`。AR3)。
- 写真・画像のファイルは作った人のフォルダ(`<作った人のID>/…`)。夫婦の相手のフォルダも読める・消せる Storage の権限を足す。
- 外部キー(予定→写真、スタンプの種類→スタンプ)を `on update cascade` にして、持ち主を付け替えられるようにする。
- **夫婦でない人は cal_owner() = 自分なので、今までと同じ動き**。テストでいちばん念入りに確かめる。

### 勤務(calendar-shifts)
- 画面から `mates: true` を付けて呼ぶと、自分の勤務に加えて、自分に見せてくれている人の勤務も返す。
- 相手の勤務記録(service_role で読む)+相手の区所のマスタ+**見る人の表記の設定** で組み立てる。範囲が「勤務だけ」なら休日はサーバーで外す。**メモは先頭の時間だけ**にしてから組み立てる(`timeOnlyMemo`。「10:00 早出」→「10:00」。時間で始まらないメモはマスタの時間に置き換わる。手で書いた言葉は相手に見せない。AR2)。相手の分が読めなかったときは、自分の勤務は返して `matesFailed: true` を付ける(画面に案内を出す。AR4)。
- 付けない(古い画面)ときは今までと同じ。

## 9. 作ったもの(2026-11-11)
### 第1段階(仲間)
- migration `20261112000000_cal_share.sql`: 表4つ(invites・links・views・sends)と関数 `cal_share_send / list / inbox_count / accept / decline / cancel / set_scope / stop`。
- `calendar-shifts`: 画面が `mates: true` を付けると、`mates: [{ ownerId, scope, couple, shifts }]` も返す(`_shared/share.ts`)。
- 画面: `web/js/share.js`(お誘いの部品)・`notices.html` の「あなたへのお知らせ」・カレンダーの設定の「👥 カレンダーの共有」・名前のラベル(id は `m:相手のID` と `m:相手のID:off`。DB のラベルではない)。

### 第2段階(夫婦)
- migration `20261113000000_cal_share_couple.sql`:
  - `cal_owner()` と `cal_partner()` を足し、cal_* の9つの表の RLS を `user_id = cal_owner()` にした(「自分だけ」のラベルとその予定・写真・テンプレートは `cal_label_hidden` / `cal_event_hidden` で隠す)。
  - `created_by` を足した。画面からは偽れず、あとから変えられない(トリガー `cal_created_by`)。
  - `cal_labels.member_id` と `private_to` を足した(`private_to` は作った人だけ)。
  - 写真・画像のパスの確かめを `created_by` のフォルダにした。予定→写真とスタンプの種類→スタンプの外部キーを `on update cascade` にした。
  - 画像は夫婦なら20枚。
  - `cal_ensure_default_labels` を夫婦に対応させた。
  - `cal_couple_start / end / move / fallback / end_for` を足した。
- 退会: 管理画面の削除(`admin-users`)は、先に `cal_couple_end_for` を呼んで持って帰ってから消す。
- `calendar-shifts`: 夫婦の相手の非番は、非番のまま返す(カレンダーに `花子・非` のラベルがあるので)。

### 決めた細かいこと(相談の内容から、作るときに決めた)
- 招待された側が作ったラベルは、予定に使っていなくても持って帰る(行き先に同じ名前があれば、それにまとめる)。
- 相手の予定に足した写真(ファイルは足した人のフォルダ)は、やめるときに消す(AR7)。画面が先にファイルを消し(やめたあとは相手のフォルダを消せないため)、`cal_couple_end` が行を消す。確認の画面に枚数を出す。退会のときは、`cal_couple_end_for` が返した場所のファイルを `admin-users` が消す。
- 相手が作った種類で押したスタンプは、種類と一緒に、種類を作った人のカレンダーにつく。
- TODO・重要メモの同時の変更は、あとから保存したほうが残る(予定だけ「相手が先に直しました」が出る)。
- 夫婦のお誘いの返事待ちは、1人1つまで。仲間の人を夫婦に誘い直すことはできる(受けると夫婦になる)。

### Storage の権限を手で作る SQL(migration で作れなかったとき)
本番の Storage の持ち主の権限で作れなかったときだけ、Supabase の SQL エディタで実行する。
```sql
drop policy if exists calendar_select_own on storage.objects;
drop policy if exists calendar_delete_own on storage.objects;
create policy calendar_select_own on storage.objects for select to authenticated
  using (bucket_id = 'calendar' and public.is_member()
         and ((storage.foldername(name))[1] = auth.uid()::text or (storage.foldername(name))[1] = public.cal_partner()::text));
create policy calendar_delete_own on storage.objects for delete to authenticated
  using (bucket_id = 'calendar' and public.is_member()
         and ((storage.foldername(name))[1] = auth.uid()::text or (storage.foldername(name))[1] = public.cal_partner()::text));
```
