# 写真取込(設計)

状態: **実装済み(2026-10-12)**。決めたことは5章(本人が決定 2026-10-12)

公開リポジトリなので、カレンダーID・個人情報・マスタの実データ・勤務表の写真は置かない。

## 1. やりたいこと

勤務指定表(1人1行・日付ごとのマスに番号)の写真から、自分の行を読み取って、勤務入力に入れる。スマホで使う前提。

## 2. しくみ

| 部分 | どこ | 内容 |
|---|---|---|
| 読み取り | Claude のアーティファクト(`https://claude.ai/artifact/GivZHYnUXZoz4uqc9dWdXV`。元のファイルは [`kinmu-photo.html`](kinmu-photo.html)) | `sample` capability(`images: true`)で、使う人の Claude に写真を送って JSON で受け取る。モデル `claude-sonnet-5-5`、丁寧さ中(「読み直す」は高・キャッシュなし) |
| 確認 | アーティファクト | 上に写真(2本指で拡大・縮小、ドラッグ、＋・−・全体)、下に勤務入力と同じ並びの表。番号を直せる(メモ欄は置かない。時間は shiftflow で入れる)。読みにくい日は黄色 |
| 受け渡し | アーティファクト → shiftflow | 勤務入力の「写真取込」は**同じタブ**でアーティファクトを開く(K1・K2)。「勤務入力に反映」= `input.html#import=<base64url>` へのリンク(新しいタブ)。開けないときや、iPhone のホーム画面アプリで使う人は「コピー」(`shiftflow-import:<base64url>`)→ 勤務入力の「貼り付けで取込」(K4) |
| 取込 | `web/js/photo-import.js`・`web/js/input.js` | 中身を確かめて、確認のあとその月の入力を置き換える(まだ保存・登録しない) |
| 保存 | 勤務入力の「保存」 | カレンダーに入れず、入力だけ保存(`save_month_records`。登録と同じく buildPlan の entries の形) |

- アーティファクトは shiftflow のサーバーに入れない(別の場所・ログインも別)。だから「登録」は shiftflow で本人が押す
- 写真はアーティファクトにもサーバーにも残さない。名前だけ、その人のブラウザに覚える
- 使う人に要るもの: Claude のアカウント(無料可)。使用量はその人のもの(上限に達すると最大5時間ほど使えない)。共有は「リンクを知っている人全員」(申請・招待は要らない)
- shiftflow の DB・Edge Functions は変えていない
- 「勤務入力に反映」は、Android では Claude のアプリの簡易ブラウザで開く。そこは普段のブラウザとログインの保存場所が別なので、1回目だけ shiftflow のログインが要る(2回目からは要らない。本人が確認 2026-10-12)。「コピー → 貼り付け」を主にする案は採らず、使い方に書くだけにした
- Claude にログインしていない人には、アーティファクトの「読み取る」を押せなくし、その下に「Claude にログインしてください」を出す。Claude のページ自体にも、ログインしていない人には「ログイン」ボタンが出る(Android で本人が確認)

## 3. 受け渡しの中身

`{ "v": 1, "y": 2026, "m": 11, "d": { "5": ["1", ""], "7": ["変7d", "9:00〜17:45"] } }` を UTF-8 の JSON にして base64url。

- 番号の無い日は入れない。メモ(2つ目)はアーティファクトでは入れないので空(受け取り側は、メモがあれば入れる形のまま)
- 「—」などの横棒は「〜」で読む。泊の翌日(非番)の番号は、取込のときに消す(メモは残す)
- 一覧にある番号は(全角でも)一覧の番号に、無い番号は手入力として入る
- 確かめること(`decodeImport`): v=1、年 2000〜2100、月 1〜12、日はその月の日、値は文字2つ、番号30文字・メモ200文字まで、改行・制御文字は空白に。全体20000文字まで
- 過ぎた月(今月より前)は取り込まない(勤務入力で表示できないため)
- 取り込んだあと、一覧(マスタ)に無い番号をメッセージに並べる。休みの番号が一覧に無ければ、登録で勤務用カレンダーに入るので管理者に追加を頼むよう出す(L3)
- 勤務入力の画面は、2秒以上隠れていて戻ったとき、登録していない変更が無ければその月を読み直す(写真取込から戻ったときに、古い画面の「登録」で上書きしないように。L1)
- アドレスの `#import=…` は読んだらすぐ消す。ログインが切れてログイン画面に移っても使えるよう、`sessionStorage` に1時間だけ覚える。画面の読み込みに失敗したときは取り出さずに残し、読み直したときに使う(K5)

## 4. 勤務表の読み方(アーティファクトの指示)

- 名前で行を探す(【眼鏡】などの印・空白は無視)。社員番号で探す案は、実機で見つからなかったのでやめた
- 名字だけ同じ人など、当てはまる人が2人以上なら見つからない扱いにして候補を出す。確認画面に読んだ行の名前を太字で出し、入れた名前と違えば赤で注意(K3)
- 全部の日が空なら読み取りの失敗(K6)
- 表の月(sheetYear・sheetMonth)が選んだ月と違えば、確認画面に赤い枠で出し、選べる月なら「◯月にする」で切り替える(L2)。月が違うことを理由に「見つからない」にしないよう指示する。見つからなかったときも表の月が違えば「月を合わせて読み直す」よう出す(実機の報告で直した。版11)
- 1日から末日までのマスの大きい文字を code、小さい文字(例「出張A」)は note(画面にだけ出す。メモに入れると一覧の時間が消えるため)
- 見出しが赤い日を holidays(平/休の表示に使う)。表の期間の年月が選んだ月と違えば知らせる

## 5. 決めたこと(2026-10-12 本人)

1. 名前はアーティファクトで入れて覚える(ログイン情報は渡せない)。社員番号では探さない
2. 取込はその月を全部置き換える
3. 取込のあとは本人が中身を見て「登録」か「保存」を押す
4. 読み取りは丁寧さ中、「読み直す」は高
5. 「保存」(登録しないで入力だけ残す)を作る。臨時などの時間をあとで入れるため
6. アーティファクトの月は今月・来月・再来月(開いた日で作る)
7. アーティファクトにメモ欄は置かない。変・臨時などの時間は shiftflow の勤務入力で入れる(黄色で目立たせる。分からなければ「保存」してあとで)
