# 勤務を時間つきの予定で登録する(設計)

状態: **実装済み(2026-10-12)**。5章は本人が決めた(2026-10-11)。migration は `20261012000000_timed_events.sql`

公開リポジトリなので、カレンダーID・個人情報・マスタの実データは書かない。

## 1. やりたいこと

TimeTree などで見る人のために、出勤を終日ではなく時間つきの予定にする。泊は2日にまたがる1件にする。

| | 今(終日) | チェックを入れたとき |
|---|---|---|
| 泊 | 泊の日に「5」(メモ: 出勤時間・泊地)、翌日に「〜」(メモ: 退勤時間) | 出勤時間から翌日の退勤時間までの1件。名前は番号、メモは泊地。「〜」は作らない |
| 日勤 | 「25」(メモ: 10:15〜19:02) | 出勤〜退勤の時間つき。メモは今のまま。退勤が出勤より前なら翌日の退勤まで |
| 休日 | 休日用に終日 | 変えない |

## 2. 設定

| チェック | 列(user_settings) |
|---|---|
| 勤務を時間つきの予定で登録する | `timed_events boolean not null default false` |

- オンのあいだは「出勤を2件」「非番を2件」「名前に時間」を使わない(画面で押せなくする。チェックは残す。サーバーも見ない)
- 次に登録する分から変わる

## 3. 時間の読み方(`toTimedEvents`)

- 泊の出勤: 泊の日のメモの1行目の先頭の時間。非番の退勤: 翌日の非番のメモの1行目の先頭の時間(`parseOffdutyTime`)。手で書き換えた時間を使う
- 先頭の時間のあとの言葉(空白で区切る。全角の空白も。空白が無くても先頭の時間を読む[Z3。「10:00大阪」])は、泊のメモに入れる(「10:30 早出」→ メモ「早出」と泊地)
- 非番のメモの時間のあとの言葉・2行目も、泊の1件のメモの後ろに続ける(Z2。「9:00 歯医者」→ 泊地のあとに「歯医者」)
- 読めない(時間で始まらない・24時以降の出勤)ときは今の終日。泊は泊・非番の2件とも終日
- 手入力の番号(マスタにない)
  - メモに「10:00〜18:00」なら日勤と同じ
  - メモが出勤時間だけ(「10:00 大阪」)で、翌日が手入力の非番(`isOffdutyTitle`)でメモに退勤時間があれば、泊と同じ1件(メモは「大阪」)
  - それ以外(翌日が非番でない・月末)は終日
  - 「〜」「公休」など、非番・休みを表す手入力は終日

## 4. 月のつなぎ目

- 月末の泊は、翌月1日の退勤時間までの1件(翌月1日の非番は作らない)。翌月1日にあるアプリの予定は今までどおり全部消す(`register-month` の `clearNextFirst` は、月末が泊なら立てる)
- 月の1日の非番(前の月の月末が泊)は、前の月の月末から1日にまたがる**時間つきの泊の1件がカレンダーにあり**、退勤時間が読めるときだけ作らない(Z1。`listAppEvents` が前の日から読むときに、またがる時間つきのアプリの予定を `carried` として返す。`deleteAppEvents` は carried を消さない)。前の月の泊が終日で登録されている(メモが時間でない・時間つきにする前に登録した)ときは「〜」を作る。こうしないと、前の月 → この月の順に登録したとき、1日の「〜」が消えて空になる
- 月末の手入力の泊はまとめない(翌月の登録からは、前の月の月末が手入力の泊かは分からないので、翌月1日の「〜」と重なるため)
- 時間つきの予定は始まりの日(日本時間)の日付で `listAppEvents` が拾うので、削除・リセットは今の印で探す仕組みのまま

## 5. 決めたこと(2026-10-11 本人)

1. 日勤のメモは今のまま(「10:15〜19:02」)
2. 設定はチェック1つ
3. 月末の泊の終わりは、その月の登録のときの翌月1日のメモで決まる。あとで翌月1日の退勤時間を直して翌月を登録しても、前の月の予定は変わらない(前の月を登録し直せば直る)
4. 切り替えた月のつなぎ目(前の月が終日のまま)は、前の月を登録し直してそろえる
5. 手入力の泊地は、メモ欄が1行なので「10:00 大阪」のように空白で区切る。月末の手入力の泊は終日のまま
