## 0. 「本番に出す」とは
作業用のブランチ(`ccr-6be58402-8udr4a`)を **main に合流**させること。main に入ると、GitHub Actions が自動で次の順に動く。
1. **Test**(Deno・DB・計算のテスト)。赤いとここで止まる(本番は変わらない)
2. **Deploy Supabase**: 新しい migration 5つを本番の DB に反映(`db push`)→ Edge Functions を全部反映(`functions deploy`)

戻す(ロールバック)は簡単ではない(下の5)。**出す前の準備が大事**。

## 5. もしものとき
- **画面だけおかしい**: GitHub で、合流のコミットを「Revert」して main に入れる(画面は前の版に戻る)。DB の変更(列・表)は残るが、前の画面は新しい列を使わないので動く(新しい列・表は、前の画面からは見えないだけ)
- **migration が途中で失敗**: Deploy Supabase が赤くなる。Pages は公開されない(今のまま)。ログを見て直してから、もう一度 push
- **Storage の権限が作れなかった**: migration は成功し、ログに注意が出る。`CHECKLIST.md` の SQL を SQL エディタで実行
- **勤務の記録が消えた**: 今回の変更は、消える範囲を**狭める**(前月1日より前 → 13か月前の月の1日より前)。新しく消えるものは無い
- **注意**: DB の変更を元に戻す migration は用意していない。戻すときは、新しい migration で列・表を消す(私が用意できる)
